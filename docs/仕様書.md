## 1. アプリケーション概要

### 1.1 目的

ユーザーが指定した駅までの直線距離を Wear OS 端末の位置情報から継続計算し、設定した距離以内に入ったとき、振動・高優先度通知・画面表示で知らせる。主用途は電車移動中の乗り過ごし防止である。

### 1.2 基本情報

| 項目 | 現行値 |
|---|---|
| アプリ表示名 | 駅近アラーム |
| UI 内タイトル | 駅近振動通知 |
| パッケージ名 | `com.example.stationalarm` |
| 言語 | Kotlin |
| UI | Jetpack Compose + Wear Compose Material |
| `compileSdk` / `targetSdk` | 34 / 34 |
| `minSdk` | 30 |
| AGP / Kotlin | 8.2.0 / 1.9.0 |
| 位置情報 | Google Play services Fused Location Provider |
| 永続化 | SharedPreferences |
| 対応言語 | 日本語のみ |

### 1.3 スコープ外

現行版は次を提供しない。

- 経路距離、線路上の残距離、到着予定時刻の計算
- 複数駅の同時監視
- 駅候補の一覧表示、地図表示、検索結果の選択
- しきい値・追跡状態・目的駅の再起動後復元
- タイルに表示する駅のユーザー編集
- 音声アラーム
- 日本語以外へのローカライズ

## 2. システム構成

### 2.1 レイヤー

```text
UI (Compose)
  ↓ 操作 / StateFlow 購読
MainViewModel
  ├─ Android Geocoder ─→ 駅名から緯度・経度を検索
  ├─ Intent ──────────→ StationAlarmService
  └─ StationRepository ←→ SharedPreferences
                            ↑
StationAlarmService ────────┘
  ↓
LocationManager
  ↓
FusedLocationProviderClient
```

| コンポーネント | 責務 |
|---|---|
| `MainActivity` | 権限要求、タイル Intent の受信、Compose の表示 |
| `StationAlarmScreen` | セットアップ画面と追跡画面の切り替え |
| `MainViewModel` | UI 状態、駅検索、サービス開始・停止 |
| `StationRepository` | 履歴の永続化、Service と UI 間のインメモリ状態共有 |
| `StationAlarmService` | フォアグラウンド追跡、距離判定、振動・通知、停止 |
| `LocationManager` | 位置更新を `Flow<Location>` として公開 |
| `StationQuickStartTileService` | 固定 3 駅のクイック起動タイル |

### 2.2 主要データフロー

```text
駅名入力
  → Geocoder の最初の検索結果
  → StationAlarmService を foreground start
  → 3 秒ごとの現在地
  → Location.distanceTo() で直線距離を計算
  → Repository の StateFlow を更新
  → ViewModel の UiState を更新
  → 追跡画面を再描画
```

## 3. 機能仕様

### 3.1 機能一覧

| ID | 機能 | 実装状態 |
|---|---|---|
| F-01 | 駅名入力・駅検索 | 実装済み |
| F-02 | 通知距離設定 | 実装済み |
| F-03 | 検索履歴 | 実装済み |
| F-04 | バックグラウンド位置追跡 | 実装済み |
| F-05 | 距離表示・接近状態表示 | 実装済み |
| F-06 | 接近アラーム | 実装済み |
| F-07 | Wear OS タイルからのクイック起動 | 実装済み |

### 3.2 駅名入力・駅検索（F-01）

1. 駅名入力欄は 1 行、中央揃えで表示する。
2. 空文字または空白だけの場合、開始ボタンを無効化する。
3. 入力値の前後空白を除去してから検索・履歴保存に使用する。
4. 検索文字列が「駅」で終わらない場合は、末尾に半角空白と「駅」を加える。
   - 例: `渋谷` → `渋谷 駅`
5. `Geocoder(application, Locale.JAPAN)` を使用する。
6. 最大 1 件を検索し、最初の結果の緯度・経度を採用する。
7. API 33 以降は非同期 `GeocodeListener`、API 32 以下は `Dispatchers.IO` 上の同期 API を使用する。
8. 同名駅の候補選択、住所確認、駅であることの検証は行わない。
9. 成功時は UI を追跡画面へ切り替え、サービス開始後に履歴を保存する。
10. 0 件または Geocoder 内の例外は「駅が見つからない」として扱う。

表示メッセージは次のとおり。

| 状態 | メッセージ |
|---|---|
| 検索開始 | 駅を検索中… |
| 検索結果 0 件 | 駅が見つかりませんでした。駅名を確認してください。 |
| `startTracking()` 内の例外 | エラーが発生しました: `{例外メッセージ}` |

検索中は `isSearching = true` とし、開始ボタンを無効化する。追跡中・検索中の再開始要求は無視する。

### 3.3 通知距離設定（F-02）

| 項目 | 現行値 |
|---|---|
| デフォルト | 500 m |
| 最小 | 100 m |
| 最大 | 2,000 m |
| 変更単位 | 100 m |
| 操作 | `－` / `＋` の `CompactButton` |
| 永続化 | しない |

- 画面上では `通知距離: XXXm` と表示する。
- ViewModel 側でも 100〜2,000 m にクランプする。
- アプリまたは ViewModel の再生成後は 500 m に戻る。
- タイル経由の開始では常に 500 m に上書きする。

### 3.4 検索履歴（F-03）

| 項目 | 現行仕様 |
|---|---|
| 保存タイミング | 駅検索成功後、サービス開始直前 |
| 最大件数 | 5 件 |
| 並び順 | 新しい順 |
| 重複 | 同一文字列を削除して先頭へ移動 |
| 保存先 | `station_prefs` / キー `history` |
| 形式 | カンマ区切り文字列 |

- 履歴チップを押すと、その文字列を駅名入力欄へ反映する。
- タップ時に LongPress 相当のハプティクスを実行する。
- 履歴の個別削除・全削除・お気に入り固定はない。
- 入力文字列を正規化しないため、前後空白や表記差は別履歴として扱う。
- カンマを含む入力は保存形式上、複数履歴として読み戻される。

### 3.5 バックグラウンド位置追跡（F-04）

| 項目 | 現行仕様 |
|---|---|
| 実行方式 | 位置情報タイプのフォアグラウンドサービス |
| 更新要求間隔 | 3,000 ms |
| 最短更新間隔 | 1,000 ms |
| 優先度 | `PRIORITY_HIGH_ACCURACY` |
| 距離計算 | `Location.distanceTo()` による地表上の直線距離 |
| サービス再起動 | `START_NOT_STICKY`。OS 終了後の自動再開なし |

サービス開始時の Intent extras は次のとおり。

| キー | 型 | 内容 |
|---|---|---|
| `STATION_NAME` | String | UI で入力した駅名 |
| `TARGET_LAT` | Double | Geocoder 結果の緯度 |
| `TARGET_LNG` | Double | Geocoder 結果の経度 |
| `THRESHOLD` | Int | 通知距離（m） |

サービス開始後は以下を行う。

1. 低重要度の監視中通知を表示する。
2. Repository の `isTracking` を `true` にする。
3. 目的駅名と「監視を開始します」を Repository に設定する。
4. 位置更新を購読し、受信ごとに直線距離を更新する。
5. アラーム発火前は監視中通知を `残り: {距離}m ({駅名})` に更新する。

位置情報精度は表示と到着判定に使用する。測定時刻、移動速度、進行方向は使用しない。開始地点がすでに通知距離以内の場合も、条件を満たす位置更新が 2 回連続した時点でアラームが発火する。

### 3.6 距離表示・接近状態表示（F-05）

追跡画面は次を表示する。

- Wear OS の時刻表示
- 画面外周の円形プログレスリング
- 接近状態メッセージ
- 目的駅名（1 行、省略記号あり）
- 現在距離（整数 m）
- 停止ボタン

距離未取得時は `位置を取得中...` と `--- m` を表示する。

プログレスは次式で計算する。

```text
maxDistance = 通知距離 × 2
progress = (maxDistance - 現在距離) / 通知距離
progress は 0.0〜1.0 に制限
```

したがって、通知距離の 2 倍以上では 0%、通知距離到達時点で 100% になる。

| 現在距離 / 通知距離 | 色 | UI メッセージ |
|---|---|---|
| `> 2.0` | 青 `#0066B3` | 🚄 移動中 |
| `> 1.0` かつ `≤ 2.0` | 緑 `#00A651` | 🚄 移動中 |
| `> 0.5` かつ `≤ 1.0` | オレンジ `#FFA500` | 📍 接近中... |
| `≤ 0.5` | 赤 `#E94560` | 🚃 まもなく到着！ |

追跡中に位置取得エラーが発生した場合は、距離状態よりエラー文言を優先して表示する。位置精度が取得できた場合は `精度 ±XXm` を表示する。

### 3.7 接近アラーム（F-06）

#### 発火条件

```text
現在距離 ≤ 通知距離
かつ 位置精度 ≤ min(通知距離, 200m)
かつ 上記を 2 回連続で満たす
かつ その追跡で未発火
```

- 1 回のサービス実行につき 1 回だけ発火する。
- GPS の一時的な飛び値を減らすため、精度条件と 2 回連続確認を行う。
- 進行方向確認とヒステリシスはない。

#### 発火時の処理

1. Repository のメッセージを「目的地に接近しました！」へ更新する。
2. `0.5 秒振動 → 0.5 秒停止` を繰り返す振動を開始する。
3. 振動を 5 秒後に停止する。
4. 高重要度のアラーム通知を通知 ID `2` で表示する。
5. `MainActivity` を直接起動して前面化を試みる。
6. 通知のフルスクリーン Intent でも `MainActivity` を開くよう要求する。
7. UI を到着専用画面へ切り替える。
8. ユーザーが「確認」を押すと振動・到着通知・追跡を終了する。
9. 未確認でも 30 秒後にサービスを自動停止する。

通知音は鳴らさない。通知チャネルと Notification Builder の両方で音を無効化し、振動は Service の `Vibrator` だけで制御する。

#### 停止時の処理

手動停止または 30 秒後の自動停止で `onDestroy()` が呼ばれると、次を行う。

- 位置購読 Job をキャンセル
- 振動停止 Job をキャンセル
- 端末の振動を停止
- Repository の `isTracking = false`
- `currentDistance = null`
- Repository の `stationName = null`
- 通常停止では Repository の `message = ""`。位置取得エラーによる停止ではエラーを保持する

UI は `isTracking = false` を受けてセットアップ画面へ戻る。ViewModel の駅名入力値、通知距離、履歴は維持される。

### 3.8 クイック起動タイル（F-07）

タイルは ProtoLayout の縦 3 チップで構成し、タイトルは表示しない。

| 項目 | 現行仕様 |
|---|---|
| 固定駅 | 西千葉 / お茶の水 / 代々木 |
| 通知距離 | 500 m 固定 |
| 更新間隔 | 1 時間 |
| 動作 | `LaunchAction` で `MainActivity` を起動 |
| Intent extra | `quick_station_name` |

- 位置権限がある場合、指定駅で即検索・追跡を開始する。
- すでに Repository 上で追跡中の場合は何もしない。ユーザーへの説明は表示しない。
- 位置権限がない場合、駅名だけ入力欄へ反映し、ユーザーの開始操作を待つ。
- 権限未取得時は通常画面と同じ位置・通知権限フローを表示し、両方が許可されれば自動的に検索・追跡を開始する。
- タイルの駅一覧、しきい値、追跡状態は永続データと連動しない。

## 4. 画面仕様

### 4.1 画面遷移

```text
アプリ起動
  └─ セットアップ画面
       ├─ 開始 → 位置・通知権限確認 → 駅検索中
       │            ├─ 成功 → 追跡画面
       │            └─ 失敗 → セットアップ画面にエラー表示
       └─ タイル Intent → 権限ありなら駅検索・追跡開始

追跡画面
  ├─ 停止 → セットアップ画面
  ├─ 通知距離到達 → 振動・通知・画面前面化
  ├─ 通知距離到達 → 到着画面 → 確認 → セットアップ画面
  └─ 到着から 30 秒 → 自動停止 → セットアップ画面
```

### 4.2 セットアップ画面

`ScalingLazyColumn` を使用し、タッチスクロールとロータリー入力に対応する。フォーカスは初回表示時にリストへ要求する。

| 順序 | 要素 | 挙動 |
|---|---|---|
| 1 | タイトル | 駅近振動通知 |
| 2 | 駅名ラベル・入力欄 | 1 行入力、中央揃え |
| 3 | 履歴 | 最大 5 個のチップ。タップで入力欄へ反映 |
| 4 | 通知距離 | `－` / 表示値 / `＋` |
| 5 | 開始 | 「追跡を開始」ラベル付き。空入力・検索中は無効 |
| 6 | メッセージ | エラーは赤、情報は青で表示 |
| 7 | 権限設定 | 再要求できない権限拒否時だけ表示 |

- 上 32 dp、下 40 dp、左右 8 dp のコンテンツ余白を設定する。
- 履歴チップの高さは 40 dp 固定である。
- 右端に `PositionIndicator` を表示する。
- 開始、履歴、距離変更の操作で LongPress 相当のハプティクスを実行する。

### 4.3 追跡画面

- 画面全面を 8 dp 幅の円形リングで囲む。
- 中央に状態、駅名、距離、単位、停止ボタンを縦配置する。
- 停止ボタンは赤色、「停止」ラベルとアイコンで表示する。
- 停止操作で LongPress 相当のハプティクスを実行する。
- 目的駅名は 1 行に制限し、長い場合は省略する。
- GPS 精度が取得できた場合はメートル単位で表示する。
- 位置取得エラーは距離状態より優先して表示する。

### 4.4 到着画面

- 赤い外周リング、完了アイコン、「到着しました」、目的駅名を表示する。
- 「確認」チップで振動・到着通知・追跡を終了する。
- 未操作の場合は 30 秒後に自動的にセットアップ画面へ戻る。

## 6. 通知仕様

### 6.1 通知チャネル

| チャネル ID | 表示名 | 重要度 | 用途 |
|---|---|---|---|
| `station_alarm_channel` | 駅近アラームサービス | LOW | 追跡中のフォアグラウンド通知 |
| `station_alarm_channel_high` | 駅到着アラーム | HIGH | 到着時のアラーム通知 |

### 6.2 通知 ID

| ID | 内容 | 特徴 |
|---|---|---|
| 1 | 監視中通知 | ongoing、タップでアプリ起動、距離ごとに更新 |
| 2 | 到着通知 | high priority、alarm category、full-screen intent、自動キャンセル |

両通知の小アイコンには、電車と到着パルスを単色化した専用ベクター `ic_station_alarm_notification` を使用する。

### 6.3 アプリアイコン

- 背景は濃紺 `#15192A`、前景は白い電車と緑 `#00A651` の到着パルスで構成する。
- 前景は Adaptive Icon の安全領域内に収め、通常・円形マスクで共用する。
- API 26 以降は背景・前景を分離した Adaptive Icon を使用する。
- API 33 以降は `monochrome` レイヤーを追加し、テーマアイコンに対応する。
- 密度別 PNG は使用せず、ベクターリソースへ統一する。
- Wear OS タイルサービスにも同じランチャーアイコンと説明文を設定する。

## 7. 権限仕様

### 7.1 Manifest 宣言

| 権限 | 現行用途・状態 |
|---|---|
| `ACCESS_FINE_LOCATION` | 高精度位置。追跡開始時に実行時要求 |
| `ACCESS_COARSE_LOCATION` | 概算位置。追跡開始時に実行時要求 |
| `FOREGROUND_SERVICE` | フォアグラウンドサービス |
| `FOREGROUND_SERVICE_LOCATION` | API 34 の位置タイプ FGS |
| `POST_NOTIFICATIONS` | Android 13 以降、追跡開始時に実行時要求 |
| `VIBRATE` | 到着振動 |
| `INTERNET` | Geocoder がネットワークを使う場合 |
| `WAKE_LOCK` | 宣言あり。アプリコードからの明示取得なし |
| `USE_FULL_SCREEN_INTENT` | 到着通知のフルスクリーン表示 |
| `TURN_SCREEN_ON` | 到着時の画面点灯 |

### 7.2 実行時フロー

1. 初回起動時には権限を要求しない。
2. 「追跡を開始」またはタイルの駅を押したとき、FINE と COARSE を同時要求する。
3. 正確な位置が許可された後、Android 13 以降では通知権限を要求する。
4. 両方の条件を満たした場合だけ駅検索を開始する。
5. 概算位置だけの場合は、正確な位置が必要であることを表示する。
6. 再要求できない拒否状態では、アプリの権限設定を開くチップを表示する。
7. 位置サービス OFF 専用の検出・案内はない。

位置タイプのフォアグラウンドサービスとして追跡するため、現行設計では `ACCESS_BACKGROUND_LOCATION` を宣言していない。

## 8. エラー・復旧仕様

| 事象 | 現行動作 |
|---|---|
| 空の駅名 | 開始ボタン無効、処理しない |
| 駅が見つからない | セットアップ画面にエラー表示 |
| Geocoder 例外 | スタックトレース出力後、駅未発見として扱う |
| 追跡中の位置例外 | 追跡画面にエラーを表示し、サービスを停止してセットアップ画面へ戻る |
| 位置権限拒否 | 理由を表示。再要求不可の場合はアプリ設定への導線を表示 |
| 概算位置のみ | 正確な位置が必要であることを表示し、追跡を開始しない |
| 通知権限拒否 | 理由を表示。再要求不可の場合はアプリ設定への導線を表示 |
| 位置サービス OFF | 専用 UI なし |
| サービスが OS に終了される | 自動再開しない |
| アプリプロセス終了 | 追跡状態を復元しない |
| タイルから追跡中に別駅を選択 | 無視し、説明しない |

## 9. 非機能仕様

### 9.1 バッテリー

- 追跡中は距離にかかわらず高精度位置を 3 秒間隔で要求する。
- 画面 OFF や駅から遠い状態でも同じ設定を継続する。
- 省電力モード、電池残量、移動速度による制御はない。

### 9.2 アクセシビリティ

- 開始、停止、増減アイコンには日本語の `contentDescription` がある。
- 色だけでなく状態テキストも変える。
- ロータリー入力でセットアップ一覧をスクロールできる。
- 履歴チップは高さ 40 dp、スクロール位置は `PositionIndicator` で表示する。
- フォント倍率別のレイアウト調整や TalkBack の自動テストはない。

### 9.3 セキュリティ・プライバシー

- 位置情報と目的駅は外部サーバーへアプリ独自送信しない。
- 駅検索には Android Geocoder を利用し、実装によってネットワーク通信が発生し得る。
- 保存するのは駅名履歴だけで、現在地は保存しない。
- `allowBackup = true` のため、駅名履歴は Android バックアップ対象になり得る。

## 11. 現行仕様の主な課題

### 11.1 重要度: 高

| ID | 課題 | ユーザー影響 |
|---|---|---|
| R-01 | Geocoder の最初の 1 件を無条件採用 | 同名駅や曖昧な入力で別地点を監視する可能性がある |
| R-02 | 追跡状態を永続化せず `START_NOT_STICKY` | プロセス終了後、ユーザーが気付かないまま監視が終わる |
| R-03 | 位置サービス OFF の専用案内がない | 権限があっても測位できない理由が分かりにくい |
| R-04 | フルスクリーン通知の利用可否を確認しない | OS 設定や端末条件により画面前面化できない場合がある |

### 11.2 重要度: 中

| ID | 課題 | ユーザー影響 |
|---|---|---|
| R-05 | 高精度 3 秒更新を常時使用 | Wear OS の電池消費が大きい |
| R-06 | タイルが開発時の固定 3 駅 | 多くのユーザーにとって実用的でない |
| R-07 | 到着判定に進行方向・ヒステリシスがない | しきい値付近で意図より早く通知する可能性が残る |
| R-08 | ウォッチ上の文字入力が中心 | 小画面で駅名を入力しにくい |

### 11.3 重要度: 低

| ID | 課題 | 影響 |
|---|---|---|
| R-09 | 履歴が CSV 形式 | カンマを含む入力を正しく保存できない |
| R-10 | タイルのプレビュー画像がない | タイル追加画面で完成状態を確認しにくい |
| R-11 | Lint に依存関係・未使用リソース等の警告が残る | 将来の SDK 更新時に保守作業が増える |

## 12. 改善提案

### 12.1 最優先: アラームの信頼性と権限 UX

#### P-01 権限を利用文脈の中で要求する（主要部分を実装済み）

- 初回起動直後ではなく、開始タップ時に位置権限を要求する。実装済み。
- 「目的駅への接近通知に位置情報が必要」と 1 画面で説明する。
- 概算位置のみ、拒否、今後表示しないを別状態として表示する。実装済み。位置サービス OFF は未対応。
- Android 13 以降では `POST_NOTIFICATIONS` を明示要求する。実装済み。
- 通知が無効なら、追跡開始前に「振動のみになる可能性」ではなく、アラームを確実に受けるための設定導線を示す。
- フルスクリーン通知の利用可否も確認し、利用不可時の代替画面・通知動作を定義する。

#### P-02 到着判定を堅牢化する（一部実装済み）

- `Location.accuracy` が許容範囲内のサンプルだけを判定に使う。実装済み。
- 2 回連続でしきい値以内の場合に発火する。実装済み。
- しきい値付近の行き来にヒステリシスを設ける。
- すでにしきい値内で追跡開始した場合は、即アラームではなく確認を表示する。
- GPS 精度を画面に表示する。実装済み。最終更新時刻は未対応。

#### P-03 到着確認画面を追加する（実装済み）

到着時は専用状態を表示する。

```text
到着しました
渋谷駅
[振動を止める / 確認]
```

- 確認ボタンで振動停止、通知消去、追跡終了を一括実行する。
- 自動終了は 30 秒に設定する。
- 追跡画面でエラー、到着画面で到着状態を表示する。

### 12.2 高優先: セットアップを短く確実にする

#### P-04 検索中状態と多重操作防止（実装済み）

- `UiState` に `isSearching` または `operationState` を追加する。
- 検索中は開始ボタン、履歴、距離変更を無効化する。
- 開始ボタンを進捗表示へ切り替える。
- サービス開始失敗を catch し、セットアップ画面へ戻して再試行を提示する。

#### P-05 駅検索結果を確認できるようにする（一部実装済み）

- Geocoder から 3〜5 件取得し、駅名と都道府県・市区町村を表示する。
- 1 件でも、追跡開始前に解決した住所を短く確認表示する。
- API 33 以降の非同期 `GeocodeListener` と入力値の trim は実装済み。
- 複数候補、住所確認、`Geocoder.isPresent()` は未対応。

#### P-06 ウォッチ向け入力へ寄せる

おすすめ順は次のとおり。

1. 最近使った駅・お気に入りを最上部に表示
2. 音声入力
3. スマートフォン側から駅を送信
4. ウォッチ上のキーボード入力

開始・停止ボタンの可視ラベルは実装済み。音声・スマートフォン入力は未対応。

### 12.3 高優先: 追跡画面の視認性

#### P-07 リングの意味を通知条件と一致させる（実装済み）

通知距離到達時にリングが 100% になるよう変更済み。

状態は `測位中 / 移動中 / 接近中 / 到着 / エラー` の明確な状態機械にする。絵文字だけに意味を持たせず、色・文言・アイコンを併用する。

#### P-08 Wear OS の操作性・アクセシビリティを整える（一部実装済み）

- `PositionIndicator` と 40 dp の履歴チップは実装済み。
- 履歴チップと操作領域を原則 48 × 48 dp、画面制約が厳しい場合も 40 × 40 dp 以上にする。
- 通知距離は Wear OS の `Picker` またはロータリーで 100 m 刻みに変更できる専用画面にする。
- TalkBack、最大フォント、最小円形画面で主要フローを確認する。

### 12.4 中優先: バッテリーと継続性

#### P-09 距離に応じた位置更新

例として、遠距離では低頻度・低消費、接近後は高精度へ切り替える。

| 状態 | 更新案 |
|---|---|
| 駅から十分遠い | Balanced、10〜30 秒 |
| 通知距離の 2〜3 倍以内 | High accuracy、3〜5 秒 |
| 通知距離付近 | High accuracy、1〜3 秒 |

実際の間隔は列車速度と実機電池を計測して決定する。更新間隔を長くする場合は、速度から到達予測を行い、接近前に高頻度へ戻す。

#### P-10 追跡セッションを復元可能にする

- 目的駅、座標、しきい値、開始時刻を DataStore に保存する。
- Service と Activity のプロセス再生成時に同じセッションを復元する。
- 自動再開するか、ユーザー確認を求めるかを仕様として決める。
- Service 終了時のルート CoroutineScope cancel は実装済み。

### 12.5 中優先: タイルを個人化する

- 固定駅を「お気に入り 2 件 + 直近 1 件」に置き換える。
- 追跡中は駅選択ではなく、目的駅・残距離・停止アクションを表示する。
- 追跡開始済みの別駅タップには、無視ではなく切り替え確認を出す。
- タイルの `icon` と `description` は実装済み。プレビュー画像は未対応。
- タップ領域の重なりと TalkBack 読み上げを確認する。

### 12.6 開発品質

#### P-11 ビルド構成を整合させる（実装済み）

- AGP 8.2.0 に合わせて Gradle Wrapper を 8.2 へ修正済み。
- Gradle 9 系を使うなら、対応する安定版 AGP・Kotlin・Compose の組み合わせへ段階的に更新する。
- milestone 版を通常ビルドの既定にしない。
- CI で `assembleDebug`、`lint`、`test` を必須化する。

#### P-12 最低限の自動テストを追加する（一部実装済み）

優先テスト対象:

1. 距離比率ごとの色・状態・リング計算（実装済み）
2. 通知距離の 100〜2,000 m クランプ
3. 履歴の重複除去・5 件制限
4. アラームが 1 回だけ発火すること
5. 権限拒否・概算位置・通知拒否の画面状態
6. タイル Intent の権限あり・なし・追跡中分岐
7. Service 停止後に追跡状態が戻ること

## 14. 受け入れ確認項目

現行版の手動確認では、最低限次を確認する。

- [ ] 初回起動では権限ダイアログが表示されず、開始操作時に表示される
- [ ] 駅名未入力では開始できない
- [ ] 駅名検索成功で追跡画面へ遷移する
- [ ] 100 m と 2,000 m の上下限を超えない
- [ ] 履歴が新しい順・最大 5 件で再起動後も残る
- [ ] 3 秒程度ごとに距離と監視中通知が更新される
- [ ] 精度条件を満たす位置が通知距離以内に 2 回連続で入ると振動が 1 回だけ始まる
- [ ] 到着画面の確認操作で振動・通知・追跡が停止する
- [ ] 未確認でも振動が 5 秒で止まり、サービスが 30 秒で止まる
- [ ] 手動停止で設定画面へ戻る
- [ ] タイルの 3 駅から追跡を開始できる
- [ ] 画面 OFF・アプリ非表示でも実機で追跡が続く
- [ ] 通知拒否、位置拒否、概算位置、位置 OFF の各挙動を確認する
